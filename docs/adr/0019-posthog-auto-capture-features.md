# 0019. PostHog の自動の収集（ヒートマップ・Web Vitals・デッドクリックなど）を使うか

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-09-27
- 関連: ADR 0007 / 0009 / 0011 / 0012 / 0014 / 0017

## 背景

ADR 0011 では、PostHog の機能のうち autocapture・Session Replay・アンケート・ページ離脱の記録だけを検討し、「決めたイベントだけを送る」とした。
PostHog のオンボーディングで、ほかにも次の機能を管理画面から有効にできることが分かった（2026-09-27）。

- ヒートマップ（Heatmaps）
- Web Vitals の自動収集（Web vitals autocapture）
- デッドクリック（押しても何も起きなかったクリック）
- 例外の自動収集（Error tracking）

これらは ADR 0011 で検討していなかった。そのうえ、PR #56 では必要かどうかを評価しないまま、これらをコードで無効にした（`capture_heatmaps` / `capture_performance` / `capture_dead_clicks` / `capture_exceptions` を `false`）。
オーナーから「必要かどうかの判断を飛ばしていないか」と指摘があり（2026-09-27）、この ADR で改めて評価する。それまでは #56 のコードを**仮の設定**として残す。

### 判断の前提

1. **PostHog は最初の操作のあとに読み込んでいる（ADR 0011 の追記）。** そのため、どの機能も「ページを開いてから最初の操作まで」を記録できない。何もせずに離脱した人のデータは取れない。
   ページを開いた時点で読み込むように変えると、初回の JS が増える（ADR 0012 の予算とのトレードオフ）。
2. **送る中身を `posthog-js@1.434.2` のソースで確かめた（2026-09-27）。**
   - ヒートマップ: `$$heatmap` のイベントで、クリックの座標（`x` / `y`）・固定要素かどうか（`target_fixed`）・操作の種類と、ページの URL を送る。**要素の文字は送らない。**
   - デッドクリック: autocapture と同じ仕組みで、要素のタグ・クラス・**要素の文字（`$el_text`、最大 1024 文字）**・要素の連なり（`$elements_chain`）を送る。**ファイル一覧の上のクリックなら、ファイル名が送られうる。** `ph-no-capture` のクラスを付けた要素は対象から外れる。
   - Web Vitals: LCP / INP / CLS などの値と URL。
   - 例外: 例外のメッセージとスタックトレース。
3. すでに決めていること。
   - Web Vitals の実利用の計測は Vercel Speed Insights（ADR 0012）。ただし ADR 0012 は、PostHog の Web Vitals と比べて選んだわけではない。
   - エラーは Sentry（ADR 0007）。
   - 録画は Sentry の「エラー時だけ・全部隠す」Replay（ADR 0007）。PostHog の Session Replay は使わない（ADR 0011 決定 2）。

## 検討した選択肢

| 機能 | 得られるもの | リスク・コスト | 前提 1（遅延読み込み）の影響 |
|---|---|---|---|
| ヒートマップ | どこが押され、どこまでスクロールされたか。ADR 0009 の新しい画面（ドロップ領域・下に固定する操作のバー）の検証に使える | 低い。座標と URL だけで、ファイル名は送らない | 大きい。最初の操作（ファイルを選ぶ・ドロップする）そのものが記録されない。追加したあとの一覧・操作のバーの上の動きは取れる |
| デッドクリック | 押せないのに押された場所。いまの UI では「点線の枠を押してもファイル選択が開かない」ことが見つかる見込み | 中くらい。要素の文字を送るので、ファイル一覧に `ph-no-capture` を付け、送る中身をテストで確かめる必要がある | 大きい。点線の枠を押すのは、たいてい最初の操作より前なので、いまの UI の問題はまさに取れない |
| Web Vitals | 速さと完了率の関係（遅い人ほど離脱しているか）。Speed Insights では見えない | 低い。量は増える（無料枠の範囲） | 致命的。遅くて何もせずに離脱した人のデータが抜け落ち、「速さと離脱の関係」がゆがむ |
| 例外の自動収集 | なし | 送り先が Sentry と 2 か所に分かれ、見落とす | — |
| Session Replay（PostHog） | 操作の様子の録画 | 画面の文字（ファイル名）が映りうる。ADR 0011 で使わないと決めている | — |

## 決定（案）

1. **この ADR を採用するまで、#56 のコードの無効化を仮の設定として残す。** 管理画面でも Autocapture・Heatmaps・Web vitals autocapture・Session Replay を Off にしておく。
2. **Web Vitals は PostHog では取らない。実利用の計測は Speed Insights（ADR 0012）にする。** 遅延読み込みのせいで離脱した人が抜け落ち、「速さと離脱の関係」という PostHog ならではの価値が成り立たないため。
   速さと完了率の関係を見たくなったら、Speed Insights の値で Web Vitals が予算を超えていることが分かった時点で、読み込みの時期ごと見直す（別の ADR）。
3. **例外の自動収集と Session Replay（PostHog）は使わない。** Sentry（ADR 0007）と重なり、Replay は ADR 0011 の判断のまま。
4. **ヒートマップとデッドクリックは、Phase 4 で新しい画面（ADR 0009）を出したあと、期間を区切って試す。**
   - いまの画面はいずれ作り直すので、いまのうちに取っても使い道が少ない。いまの UI の問題（点線の枠が押せない）は、デッドクリックを取らなくても分かっているので、ADR 0009 で直す。
   - 試すときは、次の順で行う。
     1. PostHog を読み込む時期を決める（最初の操作のあとのままか、ページを開いた時点か）。ページを開いた時点にするなら、初回の JS の増え方を ADR 0012 の予算で確かめる。
     2. デッドクリックは、ファイル名を表示する要素（一覧の行・結果の表示）に `ph-no-capture` を付け、送る中身にファイル名が含まれないことをテストで確かめてから有効にする。
     3. 期間は 2 週間。終わったら、得られたことと、続けるかどうかを「追記」に書く。
   - 試す時点で、この ADR の決定 4 をもとに ADR 0011 の「決めたイベントだけを送る」の例外として扱う。

## 結果

- 良い点: 各機能を「必要か」「何を送るか」「今の作りで価値が出るか」で評価した記録が残る。試すときの手順（特にデッドクリックのファイル名の対策）が先に決まる。
- 悪い点: Phase 4 まではヒートマップとデッドクリックのデータがない。Web Vitals と完了率の関係は当面見えない。

## オーナーに確認したいこと

2. 決定 4 の試しの期間（2 週間）でよいか。
