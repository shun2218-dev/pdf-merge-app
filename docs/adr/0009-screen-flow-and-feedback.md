# 0009. 画面の流れとフィードバック（注意事項・エラー・進捗・ページ情報）

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-09-27
- 関連: U-1 / U-2 / U-3 / U-5 / U-6 / B-8、ADR 0002 / 0003 / 0005 / 0008 / 0010 / 0011 / 0014

## 背景

いまの利用の流れは次のとおり。

1. ページを開くと注意事項のモーダルが出る。チェックを入れて「理解して閉じる」を押すまで何もできず、Esc でも外側のクリックでも閉じない（U-1）。タブを開くたびに出る（`sessionStorage`）。
2. 点線の枠にドロップするか「ファイルを選択」を押す。枠の外にドロップするとブラウザが PDF を開いてしまう（U-6）。
3. PDF 以外が混ざると `alert()` が出て、**PDF も含めて全部が捨てられる**（U-2）。
4. 並び替えはファイル名と大きさだけが手がかり（U-5）。
5. 「プレビュー」か「ダウンロード」を押す。処理中は「処理中...」の文字だけ（U-3）。失敗すると `alert()`。

ADR 0002 でファイルを端末の外へ送らなくなると、注意事項のモーダルの主な理由（「機密文書は送らないで」）がなくなる。これを機に流れ全体を見直す。
見た目は ADR 0008 のとおり、先に Claude Design で作って `docs/ui/` に置く。この ADR は、何をどの順で見せるかを決める。

## 決定

### 1. 注意事項はモーダルをやめ、画面に常に出す 1 行にする

- ドロップ領域のすぐ下に「ファイルはこの端末の中だけで処理され、外部へ送信されません」と出す（ADR 0002 決定 7。鍵のアイコン付き）。
- 免責の文言（「利用によって生じた損害について責任を負いません」など）は、フッターの「ご利用にあたって」から開くページ（`/about`）に移す。同意のチェックは求めない。
- `components/disclaimer-modal.tsx` と `sessionStorage` の `disclaimerAgreed` を消す。
- ADR 0002 が本番に出るまでは、モーダルをいまのまま残す（サーバーへ送っている間は、断りが要るため）。

### 2. 画面は 1 枚、上から「追加 → 並び替え → 結合」

| 状態 | 見せるもの |
|---|---|
| ファイルなし | 大きなドロップ領域・「ファイルを選択」・上の 1 行の断り |
| ファイルあり | 小さくしたドロップ領域（追加用）・一覧・合計（ファイル数・ページ数・大きさ）・操作のバー |
| 結合中 | 操作のバーに進捗（「3 / 8 ファイル」と進捗のバー）。一覧の操作は無効にする |
| 完了 | 結果（ページ数・大きさ）・「ダウンロード」・「プレビュー」・「最初からやり直す」 |

- 「ステップ 1 / 2 / 3」の 3 枚のカードはやめる。ファイルが 1 つあれば、次にすることは画面から分かる。
- **ドロップはウィンドウのどこでも受け付ける。** ドラッグ中は画面全体に「ここにドロップして追加」を重ねて出す。枠の外に落としてブラウザが PDF を開いてしまうのを防ぐ（U-6）。
- 操作のバーは、スマートフォンでは画面の下に固定する（一覧が長くなっても押せるように）。
- **主な操作は「結合してダウンロード」の 1 つにする。** プレビューは副次の操作（結合の結果を確かめたい人だけ）。いまの「プレビューしないとダウンロードが壊れる」（B-1）の構造をなくす。
- 出力のファイル名を変えられるようにする。既定は「最初のファイル名 + `_merged.pdf`」。
- 「すべて削除」「ファイル名順に並べる」を一覧の上に置く。

### 3. 一覧の各行に、ページ数とサムネイルを出す

- 1 ページ目のサムネイル（ADR 0003 の `react-pdf` で描く）・ファイル名・ページ数・大きさ・順番・並び替えのハンドル（ADR 0010）・削除。
- ページ数とサムネイルは、ファイルを追加した直後に Worker で読んで埋める。読めるまではスケルトンを出す。
- ページ単位の操作（特定のページだけ使う・回転する）はこの ADR では扱わない。要望が見えたら（ADR 0011 のデータで判断して）別の ADR を起こす。

### 4. エラーは「どのファイルが・なぜ・どうすればよいか」を、そのファイルの行に出す

| 状況 | 出し方 |
|---|---|
| PDF でないファイルを選んだ | PDF だけを一覧に入れ、入れなかったファイルをトースト 1 つにまとめて出す（「2 件は PDF ではないため追加しませんでした: a.docx, b.png」）。**PDF まで捨てない** |
| パスワード付きの PDF | その行に警告の印と「パスワード付きの PDF は結合できません。パスワードを外してから追加してください」。結合の対象から外す |
| 壊れた PDF | その行に同様の印と「この PDF は読み込めませんでした」 |
| 合計が大きい（ADR 0002 決定 5） | 操作のバーの上に `warning` の帯。結合はできる |
| 結合中の想定外の失敗 | 操作のバーに `destructive` のメッセージと「もう一度試す」 |

- トーストは shadcn の `sonner` を使う（ADR 0004 で一度消し、ここで足す）。トーストは消えるので、残すべき情報（行のエラー）はトーストだけに出さない。
- `alert()` は使わない（ADR 0005）。
- エラーの状態はすべてアナリティクスのイベント（ADR 0011）で数える。

### 5. 状態の変化をスクリーンリーダーにも伝える

追加・削除・並び替え・結合の開始と完了・エラーを、`aria-live="polite"` の領域で読み上げる（例: 「dummy1.pdf を 2 番目に移動しました」）。詳細は ADR 0014。

## 結果

- 良い点: 最初の操作までの手数が「モーダルを閉じる 2 手」ぶん減る。1 つのファイルの問題で全体が止まらなくなる。並び順をサムネイルで確かめられる。
- 悪い点: サムネイルの描画で、追加の直後に CPU を使う。ファイル数が多いときは、画面に入った行だけ描く。

## オーナーに確認したいこと

2. 出力のファイル名の既定（「最初のファイル名_merged.pdf」か、いまの「merged.pdf」か）。
