# 0008. デザイントークンの正本・ブランド・ライト / ダークのテーマ

- 状態: 採用
- オーナーの確認: 2026-09-27
- 日付: 2026-09-27
- 関連: D-1 / D-2 / D-3 / D-4 / C-4 / U-4、ADR 0004 / 0009 / 0014 / 0016

## 背景

- shadcn/ui の既定（無彩色の neutral）のままで、ブランドの色もロゴもない（D-2）。名前もヘッダーは「PDF Merger」、メタデータとOGP は「PDF Merge App」と揺れている。
- `<html className="dark">` でダークに固定している（D-1）。OS がライトの人にもダークを出し、`next-themes` は入っているのに使っていない。
- `--font-sans: "Geist"` を指定しているが、フォントを読み込んでいない（D-3）。環境ごとに違う書体になる。
- 「ご利用上の注意」のボタンが `destructive`（赤）で、削除や危険の色を案内に使っている（D-4）。
- `h-[800px]` のような任意値がコンポーネントに直書きされている。
- 見た目の正本（デザインファイル・スクリーンショット）がないので、「どの状態をどう見せるか」をコードを読まないと確かめられない。

## 決定

hibari の「デザイン」の決まりを、このアプリの規模に合わせて取り入れる。

1. **見た目の正本は `docs/ui/`（Claude Design から取り込んだスクリーンショットと README）にする。** 画面や状態を増やすときは、先に Claude Design で作って `docs/ui/` に置き、それから実装する。そこにない画面や状態を実装で発明しない。
2. **デザイントークンの正本は `app/globals.css` の CSS 変数だけにする**（ADR 0004 で 1 ファイルに一本化したもの）。各トークンの用途は `docs/ui/tokens.md` に書く。
   - コンポーネントに色・余白・角丸・文字サイズの値を直接書かない。Tailwind の任意値（`h-[800px]`、`text-[#fff]`）も使わない。
   - 使っていないトークン（`--sidebar-*`、`--chart-*`）は消す。
   - 色の名前は役割で付ける（`--primary`、`--destructive`、`--success`、`--warning`）。
3. **色の役割を決める。**
   - `primary` = 押せるもの（主要ボタン・リンク・フォーカスの輪）。ブランドの色をここに置く。
   - `destructive` = 削除・取り消しできない操作とエラーだけ。案内や注意には使わない（D-4）。
   - `warning` = 「このまま進められるが注意が要る」（ADR 0002 決定 5 の大きさの警告など）。
   - `success` = 結合の完了。
   - どの組み合わせも WCAG 2.2 AA のコントラスト（本文 4.5:1、大きい文字と UI 部品 3:1）を満たす（ADR 0014）。トークンの値を決めたら、組み合わせの一覧とコントラスト比を `docs/ui/tokens.md` に書く。
4. **テーマは OS の設定に従い、手動でも切り替えられるようにする。** `next-themes` を `attribute="class"`、`defaultTheme="system"` で使う。ヘッダーに「ライト / ダーク / システム」の切り替えを置く。
   ライトとダークで、同じ名前の変数を上書きして定義する。両者で色トークンの集合が一致することをテストで検査する（hibari の `globals.test.ts` と同じ）。
5. **書体は `next/font` で読み込む。** 欧文は Geist（`next/font/google`）。和文はウェブフォントを読み込まず、OS の日本語フォント（ヒラギノ角ゴシック、Noto Sans JP、Yu Gothic UI、Meiryo の順）に任せる。和文のウェブフォントは数 MB あり、1 画面のツールには見合わない（ADR 0012）。
6. **名前を 1 つに決める。** アプリ名・ヘッダー・`<title>`・OGP・README で同じ名前を使う（候補はオーナーに確認）。
7. **ロゴ（マーク）・ファビコン・Apple touch icon・OGP 画像を Claude Design で作る。** 置き場所は Next.js のファイル規約（`app/icon.svg`、`app/apple-icon.png`、`app/opengraph-image.png`）。OGP のいまの動的生成（黒地に白文字）はやめ、静的な画像にする（ADR 0016）。

## 結果

- 良い点: 見た目の判断の置き場ができ、画面が増えても一貫する。OS の設定に合った表示になる。フォントが全環境で揃う。
- 悪い点: Claude Design での作業と `docs/ui/` の取り込みが、実装の前に要る。

## オーナーに確認したいこと

1. ~~アプリの名前~~ → 回答済み（下記）
2. ~~ブランドの色の方向性~~ → 回答済み（下記）
3. ロゴ・ファビコン・OGP を Claude Design で作ることでよいか。

### オーナーの回答（2026-09-27）

- 名前も色もこだわりはない。モダンに見えて、アクセシビリティの対策の足枷にならないものにしてほしい。
- 名前は「PDF ファイルをマージできる」ことが伝わればよい。リポジトリ名は `pdf-merge-app`。
- 独自ドメイン `pdf-merge.app` を取得済み（ADR 0016）。

これを受けた案（採用の前に確認してもらう）:

- **アプリ名は「PDF Merge」にする。** ドメイン（`pdf-merge.app`）と一致し、機能がそのまま伝わる。「App」はドメインの TLD が担うので名前に入れない。ヘッダー・`<title>`・OGP・README をこれに揃える（決定 6）。
- **ブランドの色は、彩度を抑えた青（インディゴ寄り）を `primary` にする。** 理由:
  - 赤は PDF（Adobe）の色と `destructive`（削除・エラー）と衝突する。緑は `success` と衝突する。青は状態の色（成功・警告・エラー）のどれとも重ならず、「押せるもの」の色として一般的なので、色の役割（決定 3）を崩さない。
  - ライトでは白い文字を載せてもコントラスト 4.5:1 以上、ダークでは暗い背景の上で 3:1 以上になる明度を選ぶ。色の値は `oklch` で決め、組み合わせのコントラスト比を `docs/ui/tokens.md` に書く。
  - 色だけで状態を伝えない（アイコンと文言を必ず添える）ことも、ADR 0014 と合わせて守る。

**オーナーの回答（2026-09-27）**: すべて提案どおりでよい。アプリ名は「PDF Merge」、ブランドの色はインディゴ寄りの青でよい。ロゴ・ファビコン・OGP は Claude Design で作る。
