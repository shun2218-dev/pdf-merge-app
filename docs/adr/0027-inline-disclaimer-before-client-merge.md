# 0027. 注意事項は、自動で開くモーダルをやめ、ドロップ領域の下に常に出す（ADR 0002 より前に）

- 状態: 採用
- オーナーの確認: 2026-10-03
- 日付: 2026-10-03
- 関連: docs/assessment.md の U-1 / M-4 / ADR 0002 / 0009 / 0023 / 0025 / 0026

## 背景

ADR 0025 の基準の端末で、TBT が関門（200 ms）を超えている。ADR 0026 でブラウザの Sentry を load のあとに回したが、CI では 173〜212 ms で、関門の前後にとどまった（ADR 0026 の追記）。

CI で部品を外したビルドを並べて測った内訳（ADR 0026 の追記。基準の端末の条件、3 台、TBT の中央値）では、残りの大半は注意事項のモーダルの自動表示だった。

| ビルド | TBT |
|---|---|
| ADR 0026 | 173〜200 ms |
| ADR 0026 ＋ モーダルを自動で開かない | 128〜149 ms |
| Next.js と React だけ（Sentry・モーダル・結合の画面・Web Vitals を外す） | 120〜138 ms |
| ADR 0026（Sentry 有効。本番と同じ） | 197〜239 ms |

- モーダルは、ページを表示したあとに `useEffect` で開く（`components/header.tsx`）。そのため、最初の描画のすぐあとに、ダイアログ（Radix）を描くための 2 回目の描画が走り、45〜53 ms の TBT になっている。
- ADR 0025 の実装では、CI を Sentry 有効（送り先のないダミーの DSN）で測ることにした（ADR 0025 の追記。2026-10-03）。この条件では、ADR 0026 のあとでも 197〜239 ms ある。モーダルの分を減らさないと、関門の内に入らない。

一方、注意事項の見せ方は ADR 0009 決定 1 で決めてある。

- 注意事項はモーダルをやめ、ドロップ領域のすぐ下に常に出す 1 行にする。免責の文言は `/about` に移し、同意のチェックは求めない（オーナーの回答 2026-09-27）。
- ただし **ADR 0002（結合をブラウザの中に移す）が本番に出るまでは、モーダルをいまのまま残す**（サーバーへ送っている間は、断りが要るため）。

この「ADR 0002 まで残す」は、断りを出し続ける必要から決めたもので、出し方がモーダルである必要まではない。また、いまのモーダルはタブを開くたびに出て、チェックを入れないと閉じられず、最初の操作までの手数が多い（U-1）。読まずに閉じられやすい出し方でもある。

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. いまのまま（ADR 0002 まで、モーダルを自動で開く） | 変更がない | TBT が関門を超えたまま。#81（Next.js 16）の判定も進まない |
| B. モーダルを、最初の操作（ファイルを選ぶ・ドロップする）のときに開く | 同意のチェックを残せる | 操作のたびに 2 回目の描画が操作の直後に移るだけで、INP が悪くなる。操作を止める手数は残る |
| C. モーダルを、load のあとに遅らせて開く | 変更が小さい | 表示のあとにモーダルが飛び出す。Lighthouse の TBT が数える範囲にまだ入りうる |
| **D. ADR 0009 決定 1 の出し方を前倒しする。断りの文言は、サーバーへ送っている間のものにする** | 2 回目の描画がなくなる。断りが、ファイルを入れる場所に常に見えている。ADR 0009 の最終形にそのままつながる | 同意のチェックがなくなる（ADR 0009 で了承済み）。`/about` はまだないので、免責の文言の置き場を決める必要がある |

## 決定

1. **注意事項のモーダルをやめる。** `components/disclaimer-modal.tsx`、ヘッダーの「ご利用上の注意」のボタン、`sessionStorage` の `disclaimerAgreed` を消す。ADR 0009 決定 1 の「ADR 0002 が本番に出るまでは、モーダルをいまのまま残す」を、この ADR で置き換える（ほかの決定はそのまま）。
2. **断りは、ドロップ領域のすぐ下に常に出す。** 文言は、サーバーへ送っている間のものにする。
   - 「PDF は結合のためにサーバーへ送信します。サーバーには保存せず、処理のあとに破棄します。」
   - 「社外秘の文書や個人情報を含むファイルは、アップロードしないでください。」（いまのモーダルと同じく、目立つ色で出す）
   - ADR 0002 が本番に出たら、ADR 0009 決定 1 の文言（「ファイルはこの端末の中だけで処理され、外部へ送信されません」）に替える。
3. **断りは、ブラウザの JS を使わずに描く。** サーバーコンポーネントで描き、結合の画面（クライアントコンポーネント）には props で渡す。断りのために、読み込みのあとの描画を増やさない。
4. **免責の文言（「利用によって生じた損害について責任を負いません」）は、`/about` ができるまで、断りの下に小さく出す。** `/about` は ADR 0009 決定 1 のとおり、Phase 4 で作り、そのときに移す。
5. **同意のチェックは求めない**（ADR 0009 のオーナーの回答のとおり）。

## 結果

- 良い点: TBT から 2 回目の描画の分（CI で 45〜53 ms）がなくなる見込み。ダイアログのコードも最初の読み込みから外れる。最初の操作までの手数が減る（U-1）。断りが、ファイルを入れる場所に常に見えている。
- 悪い点: 同意のチェックがなくなるので、「読んで同意した」という記録は残らない（いまもタブを閉じれば消えるので、記録として使ってはいない）。
- あとで困りうること: Sentry 有効の条件で、まだ関門の内に入らないかもしれない（ADR 0026 の Sentry 有効の値から、モーダルの分を引くと 150〜190 ms ほどの見込み。推定なので、実装のあとに CI で測る）。入らなければ、結果を追記に書いて相談する。

## オーナーに確認したいこと

1. 案 D（モーダルをやめ、サーバーへ送っている間の断りをドロップ領域の下に常に出す）で進めてよいか。
2. 決定 2 の文言でよいか。
3. 免責の文言を、`/about` ができるまで断りの下に小さく出すこと（決定 4）でよいか。

**オーナーの回答（2026-10-03）**: すべて提案どおりでよい。
