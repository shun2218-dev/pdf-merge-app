# 0031. 結合した PDF のファイル名を利用者が入力できるようにし、既定は「merged_ + ダウンロードした日時」にする（ADR 0009 より前に）

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-10-09
- 関連: ADR 0007 / 0009 / 0011 / 0013 / 0014 / 0027 / 0030

## 背景

結合した PDF は、いつも `merged.pdf` という名前でダウンロードされる（`constants/index.ts` の `DOWNLOAD_FILE_NAME`。`hooks/use-merge-workflow.ts` の `download` と、プレビューのツールバーのダウンロード（`components/pdf-preview.tsx` の `fileNameGenerator`）が使う）。何度か結合すると、ダウンロードのフォルダに `merged.pdf`・`merged (1).pdf`… が並び、どれが何か分からなくなる。

オーナーから次の要望があった（2026-10-04）。

- 結合したあとのファイル名を、利用者が入力できるようにしたい。
- 既定は「固定の文字 + ダウンロードしたときの日時」（例: `merged_yyyymmddhhmmss`）。
- できるだけ早くリリースに入れたい（2026-10-09）。

これには次の食い違いがある。

1. **ADR 0009 決定 2 と既定が違う。** ADR 0009 決定 2 は「出力のファイル名を変えられるようにする。既定は『最初のファイル名 + `_merged.pdf`』」で、オーナーが 2026-09-27 に了承している。採用した決定は書き換えないので（ADR 0001）、この項目をこの ADR で置き換える。
2. **ADR 0009 は Phase 4。** 画面の作り直し（3 枚のカードをやめる・操作のバーなど）と一緒に入れる予定だった。この項目だけを前倒しする（ADR 0027 で注意事項だけを前倒ししたのと同じ扱い）。
3. **ADR 0030 決定 6 で、Phase 3 の最初のリリースは ADR 0002 だけにした。** v1.4.0（ADR 0002）はそのまま出し、この ADR は次のリリース（v1.5.0）で単独で出す（オーナーの判断 2026-10-09）。決定 6 は変えない。

ほかに、決めておかないと実装で迷うことがある。

- 日時はどの時刻か（ブラウザのローカル時刻か UTC か、結合したときかダウンロードしたときか）。
- 利用者が `.pdf` を付けたとき・付けなかったとき。
- ファイル名に使えない文字（Windows の `/ \ : * ? " < > |` など）と長さ。ブラウザは `download` 属性の名前を自分で直すが、直し方がブラウザごとに違う（`_` に置き換える・名前を捨てて既定の名前にする など）。
- 入力したファイル名は、ファイル名そのものと同じく利用者の情報なので、アナリティクス・Sentry に送ってはいけない（ADR 0007 / 0011）。いまのアナリティクスは `download_clicked` に `renamed`（いまは常に `false`）を持っている（ADR 0011）。

## 検討した選択肢

**入力欄の最初の値**

| 案 | 良い点 | 悪い点 |
|---|---|---|
| **A. 空にしておき、空のままなら既定の名前（ダウンロードした時刻）を使う。既定の形は入力欄の下に出す** | 時刻を「ダウンロードしたとき」にそのまま合わせられる。触らない人には何も増えない | 入力欄に名前が見えないので、既定の名前がそのまま使われることを、説明の文で伝える必要がある |
| B. 結合の画面に入ったときの時刻で、既定の名前を入れておく | 実際の名前が見える。少し変えるだけで使える | 入れた時刻とダウンロードした時刻がずれる（オーナーの要望と違う）。入れ直すかどうかの扱いが増える |
| C. ダウンロードを押したときに、名前を聞くダイアログを出す | 名前を必ず意識できる | 操作が 1 つ増える。ADR 0009 の「1 回でダウンロード」に反する |

**使えない文字**

| 案 | 良い点 | 悪い点 |
|---|---|---|
| **ア. 使えない文字を `_` に置き換えてダウンロードする。入力は止めない** | 必ずダウンロードできる。ブラウザごとの差をなくせる | 入力した名前と少し違う名前になる（説明の文で伝える） |
| イ. 使えない文字があればエラーにして、ダウンロードできなくする | 入力した名前のとおりになる | 操作が止まる。理由を読んで直す手間が増える |

## 決定

1. **ステップ 3 に「ファイル名」の入力欄を置く。** ボタンの上に置き、入力欄の右に `.pdf` を固定の文字で出す。見えるラベル（`<label>`）を付け、既定の名前と置き換えの説明は `aria-describedby` で読み上げる（ADR 0014）。Phase 4 の画面の作り直し（ADR 0009）では、操作のバーに移す。
2. **入力欄は最初は空にし、空のままなら既定の名前を使う（案 A）。** 既定の名前は `merged_` + ダウンロードを押したときのブラウザのローカル時刻を `yyyyMMddHHmmss`（24 時間制・0 埋め）で並べたもの（例: `merged_20261009143005.pdf`）。入力欄の下に「空欄のときは merged_年月日時分秒.pdf になります（ダウンロードした時刻）」と出す。ADR 0009 決定 2 の「既定は最初のファイル名 + `_merged.pdf`」を、この決定で置き換える。
3. **`.pdf` は自動で付ける。** 入力した名前が `.pdf` で終わっていれば（大文字・小文字は問わない）重ねて付けない。
4. **使えない文字は `_` に置き換える（案ア）。** 置き換えるのは `/ \ : * ? " < > |` と制御文字。前後の空白と、末尾のドット・空白は取り除く（Windows で使えないため）。置き換えたあとに空になったら、既定の名前を使う。長さは `.pdf` を除いて 80 文字までにする（入力欄の `maxLength`。日本語でも UTF-8 で 240 バイトに収まり、多くのファイルシステムの上限 255 バイトの内に入る）。
5. **同じ名前を、ダウンロードのボタンとプレビューのツールバーのダウンロードの両方に使う。** プレビューのツールバーは ADR 0003 で `react-pdf` に移すときに消える。
6. **入力したファイル名は、アナリティクス・Sentry・ログに送らない（ADR 0007 / 0011）。** `download_clicked` の `renamed` に「入力欄に何か入れてダウンロードしたか」（`true` / `false`）だけを送る。新しいイベントは足さない。入力欄の値は、結合の状態（reducer）とは別に持ち、名前を変えても結合し直さない。一覧を変えても、ページを読み込み直すまでは入力した名前を残す。
7. **文言は `constants` に寄せる。** Phase 5 の i18n（ADR 0013）で辞書に移す。
8. **v1.4.0（ADR 0002）の次のリリース（v1.5.0）で、この ADR だけを出す。** ADR 0030 決定 6 は変えない。ADR 0009 のほかの決定は Phase 4 のまま。

## 結果

- 良い点: 結合した PDF を、利用者が分かる名前で保存できる。触らない人でも、ダウンロードのたびに違う名前（日時）になり、`merged (1).pdf` のような名前が並ばない。どのブラウザでも同じ名前でダウンロードされる。
- 悪い点: ステップ 3 に入力欄が 1 つ増える。Phase 4 の画面の作り直しで、置き場所を変えることになる。
- あとで困りうること: 既定の名前は英語の `merged_` なので、Phase 5 の英語版ではそのままでよいが、日本語の名前（例: `結合_`）を望む声が出たら見直す。iOS の Safari は、ファイルの保存のときに名前を変えることがある（E2E の WebKit で、`download` の名前が渡ることまでは確かめる）。

## オーナーに確認したいこと

1. 入力欄は最初は空にし、空のままなら「merged_ + ダウンロードした時刻」を使う（決定 2・案 A）でよいか。それとも、既定の名前を最初から入れておく（案 B）がよいか。
2. 使えない文字は `_` に置き換えてダウンロードする（決定 4・案ア）でよいか。長さの上限（80 文字）はこれでよいか。
3. ADR 0009 決定 2 の既定（最初のファイル名 + `_merged.pdf`）を、この ADR で置き換えてよいか。

リリースの分け方（決定 8）は、オーナーが 2026-10-09 に決めた（v1.4.0 は ADR 0002 だけで出し、この ADR は次のリリースで出す）。
