# 0003. プレビューを @react-pdf-viewer から最新の pdfjs-dist（react-pdf）へ移す

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-09-27
- 関連: B-3 / C-10 / U-4、ADR 0002 / 0009 / 0012 / 0017

## 背景

- プレビューは `@react-pdf-viewer/core@3.12.0` と `pdfjs-dist@3.11.174` で描いている。
- **`pdfjs-dist` 4.1.392 以前には CVE-2024-4367 がある。** フォントの処理で、細工した PDF から任意の JavaScript を実行できる。4.2.67 で修正された。
  いまは利用者が自分で選んだ PDF しか開かないが、「メールで受け取った PDF を結合する」のはよくある使い方で、自分で選んだ PDF が安全とは限らない。
  しかも ADR 0002 でファイルをブラウザ内だけで扱うようにすると、このページの中の実行はそのままファイルの中身に届く。
- **`@react-pdf-viewer` は 2023-03 から更新が止まっていて、pdfjs 4 以降に対応していない。** ライブラリの版を上げて直すことができない。
- ワーカー（`public/lib/pdf.worker.min.js`、1MB）を手でコピーして置いているので、`pdfjs-dist` の版とずれても気づけない（C-10）。
- 高さ 800px とダークテーマが固定で、スマートフォンでは画面より高く、ライトテーマにも合わない（U-4）。

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. ブラウザ標準のビューア（`<iframe src={blobUrl}>`） | 依存ゼロ。最速 | Android の Chrome は iframe で PDF を描かずダウンロードになる。iOS の Safari は最初のページしか見えないことがある。見た目を揃えられない |
| B. `pdfjs-dist` の最新を直接使う | 依存が最小。全部を制御できる | ページの描画・遅延読み込み・テキスト層を自前で書く量が多い |
| **C. `react-pdf`（wojtekmaj）を使う** | 最新の pdfjs に追従してメンテナンスされている。`<Document>` / `<Page>` だけで描ける。サムネイル（ADR 0009）にも同じ部品を使える | ツールバー（拡大・検索など）は自前 |
| D. pdf.js 公式の汎用ビューアを iframe で置く | 機能が全部入り | 重い。見た目を合わせにくい |

## 決定

**C を採る。プレビューとサムネイルは `react-pdf` で描き、`@react-pdf-viewer` を外す。**

1. **暫定策（Phase 1）: いまのビューアのまま `isEvalSupported: false` を渡す。** CVE-2024-4367 の公開されている回避策。
   `@react-pdf-viewer` の `Viewer` の `transformGetDocumentParams` で `getDocument` の引数に足す。この props が 3.12.0 で使えない場合は、暫定策をあきらめて決定 2 を Phase 1 に前倒しする。
2. **本対応（Phase 3）: `react-pdf` に置き換える。**
   - ワーカーは `new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)` でバンドラに解決させ、`public/lib/pdf.worker.min.js` を消す（C-10）。
   - `react-pdf` が依存する `pdfjs-dist` の版を `pnpm` の `overrides` で固定し、4.2.67 未満にならないようにする。
   - プレビューは、プレビューを開いたときにだけ `next/dynamic` で読み込む（初回の JS に入れない。ADR 0012）。
   - ページは縦に並べ、画面に入ったページだけ描く（`IntersectionObserver`）。100 ページの PDF でも一度に 100 枚の canvas を作らない。
   - 幅はコンテナに合わせ、高さは固定しない。テーマはアプリのテーマ（ADR 0008）に従う。
   - ツールバーは「前 / 次のページ」「ページ番号」「拡大 / 縮小」「ダウンロード」だけにする。検索・印刷・全画面は付けない（元のブラウザの機能で足りる）。
3. **ファイルごとのサムネイル（ADR 0009）も同じ `react-pdf` の `<Page>` で描き、描画の部品を 1 つにする。**

## 結果

- 良い点: 既知の脆弱性がなくなり、今後も pdfjs の更新に追従できる。ワーカーの手作業のコピーがなくなる。プレビューの見た目をアプリに合わせられる。
- 悪い点: いまのビューアにある検索・サムネイルの側栏・全画面・印刷がなくなる。必要なら後で ADR を起こして足す。
- 注意: `react-pdf` の CSS（テキスト層・注釈層）を読み込むかは、描画の品質とバンドルサイズを見て実装時に決め、「追記」に書く。
