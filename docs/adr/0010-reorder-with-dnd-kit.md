# 0010. ファイルの並び替えを dnd-kit にする（タッチ・キーボード対応）

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-09-27
- 関連: B-7 / A-1、ADR 0005 / 0009 / 0014

## 背景

- 並び替えは HTML5 の Drag and Drop（`draggable` と `onDragOver`）で書いている。
- **HTML5 の Drag and Drop はタッチに対応していないので、スマートフォンでは並び替えられない（B-7）。** Playwright の設定には Pixel 5 と iPhone 15 があるが、E2E は `dispatchEvent` で擬似的にイベントを投げているので、実際には動かないことを検出できていない。
- **キーボードでも並び替えられない。** biome の `noStaticElementInteractions` を「キーボードの代替手段を別に用意している」という理由で抑止しているが、その手段は存在しない。
- `onDragOver` のたびに `onReorder` を呼ぶので、ドラッグ中に並びが何度も入れ替わり、`key` が `index` を含むこと（B-6）と合わさって行がちらつく。

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. HTML5 DnD のまま、上下の移動ボタンを足す | 依存が増えない | タッチでドラッグできない。ボタンだけでは 20 ファイルの並び替えがつらい |
| **B. `@dnd-kit/core` + `@dnd-kit/sortable`** | ポインタ・タッチ・キーボードのセンサーが揃い、スクリーンリーダー向けの読み上げの仕組みもある。縦の一覧の並び替えの実績が多い | 依存が 2 つ増える（gzip で十数 KB） |
| C. `react-aria` の `useDragAndDrop` | a11y の作りが最も丁寧 | react-aria のほかの部品と揃えないと浮く。shadcn（Radix）と混ざる |
| D. `@atlaskit/pragmatic-drag-and-drop` | 軽い | キーボード操作は自前 |

## 決定

**B を採る。**

1. `@dnd-kit/sortable` の `SortableContext`（縦のリスト）で一覧を並べ替える。並びの識別子は ADR 0005 の `id`。
2. センサーは 3 つ。
   - ポインタ: 5px 動いたらドラッグを始める（クリックと区別する）
   - タッチ: 200ms 押し続けたらドラッグを始める（縦のスクロールと区別する）
   - キーボード: ハンドルにフォーカスして Space で持ち上げ、↑↓ で動かし、Space で置く、Esc で取り消す
3. **ドラッグできるのはハンドルだけにする。** 行全体をドラッグ可能にすると、スマートフォンで一覧をスクロールしにくくなるため。ハンドルは 44×44px 以上のタップ領域を持つ（ADR 0014）。
4. **並びを確定するのは置いたとき（`onDragEnd`）だけ。** ドラッグ中は dnd-kit の見た目の移動だけで、state を変えない。
5. 各行のメニュー（…）に「上へ移動」「下へ移動」「先頭へ」「末尾へ」も置く。ドラッグという操作に気づかない人と、スイッチ操作などの支援技術の人のため。
6. 読み上げの文言（`announcements`）は日本語と英語で用意し（ADR 0013）、「dummy1.pdf を持ち上げました。いまは 1 番目です」「3 番目に移動しました」のように、ファイル名と位置を伝える。
7. `prefers-reduced-motion` のときは、移動のアニメーションを切る。
8. biome の a11y の抑止コメントを消す。

## 結果

- 良い点: スマートフォン・キーボード・スクリーンリーダーのどれでも並び替えられる。ドラッグ中のちらつきがなくなる。
- 悪い点: 依存が増える。E2E で実際のポインタ操作（`mouse.down` / `move` / `up`）を使う必要があり、テストが少し長くなる。
