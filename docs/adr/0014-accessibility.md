# 0014. アクセシビリティの目標（WCAG 2.2 AA）と検査の自動化

- 状態: 提案
- オーナーの確認: 未
- 日付: 2026-09-27
- 関連: A-1 / A-2 / B-7 / Q-4、ADR 0005 / 0006 / 0008 / 0009 / 0010 / 0012 / 0013

## 背景

- 並び替えがキーボードでもタッチでもできない（B-7）。
- ファイルの追加・削除・並び替え・結合の完了が、スクリーンリーダーに伝わらない（A-1）。
- 各行に `aria-label="File List"`（英語・全行同じ）が付き、削除ボタンの名前が「削除する」だけで、どのファイルの削除か分からない（A-2）。
- 注意事項のモーダルが Esc で閉じない（キーボードで閉じる手段がボタンだけ）。
- Storybook の a11y 検査は `test: "todo"` で、違反があっても落ちない（Q-4）。E2E には a11y の検査がない。
- 目標の水準が決まっていないので、「どこまでやれば十分か」を判断できない。

## 決定

1. **目標は WCAG 2.2 の AA とする。** 特に次の基準を重く見る（このアプリで破りやすいもの）。
   - 2.1.1 キーボード / 2.5.7 ドラッグ操作（ドラッグの代わりになる操作がある。ADR 0010 決定 5）
   - 2.4.7 フォーカスの可視化 / 2.4.11 フォーカスが隠れない（スマートフォンで下に固定する操作のバー（ADR 0009）に、フォーカスした行が隠れない）
   - 2.5.8 ターゲットのサイズ（最小 24×24px。主要な操作と並び替えのハンドルは 44×44px）
   - 1.4.3 / 1.4.11 コントラスト（ADR 0008 決定 3）
   - 4.1.3 ステータスメッセージ（追加・削除・並び替え・結合の進捗と完了・エラーを `aria-live` で伝える）
2. **自動の検査を 3 段で行い、CI で落とす（ADR 0006）。**
   - Storybook: `a11y.test` を `"error"` にし、全ストーリーで axe の違反を 0 にする。
   - E2E: `@axe-core/playwright` で、ADR 0009 の 4 つの状態（ファイルなし / あり / 結合中 / 完了）とエラーの状態を検査する。ライトとダークの両方。
   - Lighthouse CI: Accessibility 100（ADR 0012）。
3. **自動の検査で見つからないものは、手動の確認の一覧（`docs/a11y.md`）で確かめる。** リリースの前（`release/*`）に 1 回、次を行う。
   - キーボードだけで、追加 → 並び替え → 削除 → 結合 → ダウンロードができる
   - VoiceOver（macOS の Safari・iOS の Safari）で同じ流れができ、状態の変化が読み上げられる
   - 200% の拡大・幅 320px で、横スクロールなしに使える
   - `prefers-reduced-motion` でアニメーションが止まる
   - Windows のハイコントラスト（`forced-colors`）で、ボタンとフォーカスが見える
4. **フォーカスの移り先を決める。**
   - 行を削除したら、次の行（なければ前の行、それもなければドロップ領域の「ファイルを選択」）へ。
   - 結合が完了したら、結果の見出しへ。
   - ダイアログやメニューを閉じたら、開いたボタンへ（Radix の既定）。
5. **名前の付け方を決める。** 各行は `<li>` にしてファイル名で名前を付ける。行の中のボタンは「dummy1.pdf を削除」のように対象を含める（ADR 0013 の辞書で組み立てる）。装飾のアイコンは `aria-hidden`。
6. **biome の a11y の抑止（`biome-ignore lint/a11y/*`）を原則として使わない。** どうしても要るときは、理由と代替の手段を PR に書く。

## 結果

- 良い点: 「どこまでやるか」の基準ができ、退行を CI で止められる。キーボード・スクリーンリーダー・スマートフォンの利用者がすべての操作をできる。
- 悪い点: ストーリーと E2E に a11y の検査が加わり、CI が少し延びる。手動の確認をリリースのたびに行う手間がある。
