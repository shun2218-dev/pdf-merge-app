# 0002. PDF の結合をブラウザ内で行い、サーバーへ送らない

- 状態: 採用
- オーナーの確認: 2026-09-27
- 日付: 2026-09-27
- 関連: B-2 / B-4 / P-1 / P-4、ADR 0003 / 0009 / 0017

## 背景

いまは選んだ PDF をすべて `POST /api/merge-pdf` に送り、サーバーの `pdf-lib` で結合して返している。これが次の問題を生んでいる。

- **4.5MB を超えると結合できない（B-2）。** Route Handler は Node.js の Vercel Functions で動き（README の「Edge Runtime」は誤り）、リクエスト本文の上限が 4.5MB。スキャンした PDF なら 2〜3 ファイルで超える。
- **機密文書を扱えない（P-1）。** 注意事項で「社外秘・個人情報を含むファイルは送らないで」と断っているが、PDF を結合したい場面（契約書・請求書・履歴書・確定申告の書類）の多くはまさにそれに当たる。モーダルで断るのは、問題を利用者に押し付けているだけ。
- **往復の分だけ遅い。** 10MB を結合すると、上り 10MB と下り 10MB の転送が必ず発生する。
- **濫用に弱い（P-4）。** 数・サイズ・頻度の制限がなく、関数の実行時間とメモリを使われ放題。
- 暗号化された PDF が 1 つでもあると全体が 500 になり、どのファイルが悪いのか分からない（B-4）。

`pdf-lib` はブラウザでもそのまま動く。サーバーで結合する理由は、いまのところない。

## 検討した選択肢

| 案 | 良い点 | 悪い点 |
|---|---|---|
| A. いまのまま（サーバーで結合）＋上限をエラー文言で案内 | 変更が小さい | 4.5MB の壁とプライバシーの問題が残る |
| B. サーバーのまま、署名付き URL で Blob / S3 に上げて処理 | 上限は外れる | ファイルが第三者のストレージに残る。構成とコストが増え、プライバシーはむしろ悪化 |
| **C. ブラウザ内（Web Worker）で `pdf-lib` を動かす** | 上限は端末のメモリだけ。ファイルが端末の外に出ない。サーバー費用ゼロ。オフラインでも動く | 古い端末では大きいファイルで遅い / メモリ不足になりうる |
| D. ブラウザ内で MuPDF（WASM）を使う | 壊れた PDF や暗号化にも強い | WASM が数 MB と重い。AGPL のため配布の条件が厳しい |

## 決定

**C を採る。結合はブラウザの Web Worker で行い、PDF の中身を一切サーバーへ送らない。**

1. **結合の処理は `lib/pdf/merge.ts` の純粋な関数にする。** 入力は `{ id, name, bytes: ArrayBuffer }[]`、出力は結合した `Uint8Array`。DOM にも React にも依存させず、Vitest で直接テストする。
2. **Web Worker で動かす。** `workers/merge.worker.ts` が 1 を呼ぶ。`ArrayBuffer` は Transferable で渡してコピーを避ける。1 ファイル読み終えるごとに `{ type: "progress", done, total }` を返し、進捗の表示（ADR 0009）に使う。
   Worker を作れない環境（ごく古いブラウザ）では、メインスレッドで 1 を呼ぶ。
3. **ライブラリは当面 `pdf-lib@1.17.1` を版固定で使う。** 更新は 2021 年で止まっているが、結合に使う API（`load` / `copyPages` / `save`）は安定している。
   `@cantoo/pdf-lib`（メンテナンスされているフォーク）への切り替えは、実装時に互換性とバンドルサイズを比べて「追記」に書く。
4. **入力の検証はファイルごとにする。**
   - PDF かどうかは `file.type` ではなく、先頭のバイトが `%PDF-` かで判定する（B-8。拡張子 `.pdf` で MIME が空の環境でも受け付ける）。
   - 暗号化された PDF は `pdf-lib` の `EncryptedPDFError` で見分け、そのファイルだけ「パスワード付きの PDF は結合できません」として一覧に印を付ける。ほかのファイルの結合は止めない（どう見せるかは ADR 0009）。
   - 壊れていて読めない PDF も、同じくファイル単位で印を付ける。
5. **上限は「禁止」ではなく「警告」にする。** 端末のメモリ次第なので、固定の上限で弾かない。合計 300MB または 100 ファイルを超えたら「端末によっては時間がかかるか失敗します」と出す（値は Phase 1 の計測で見直す）。
6. **`app/api/merge-pdf/route.ts` は、ブラウザ版を本番に出した次のリリースで消す。** 1 リリースだけ残すのは、問題が出たときに戻せるようにするため。消すときに `__tests__/api/merge-pdf.test.ts` も消す。
7. **注意事項の文言を「ファイルはこの端末の外へ送信されません」に改める（ADR 0009）。** この約束を破らないよう、E2E で「結合の操作中に、PDF を本文に含むリクエストが 1 件も出ない」ことを検査し、CSP の `connect-src` でも絞る（ADR 0017）。

## 結果

- 良い点: 4.5MB の壁がなくなる。機密文書を扱えるようになり、注意事項のモーダルという摩擦（U-1）も外せる。API がなくなるので、濫用・費用・サーバー側のエラー監視の心配がなくなる。
- 悪い点: 性能が利用者の端末に左右される。低スペックのスマートフォンで数百 MB を結合すると、タブが落ちうる（決定 5 の警告で和らげる）。
- 注意: README の「Edge Runtime によるPDF処理」の節は事実と異なるので、この ADR の実装と同時に書き直す。

## 追記

### 2026-10-04: 決定 5 の見直しの時期を ADR 0030 で置き換えた

- 本番のアクセスがほとんどなく、「警告のしきい値は Phase 1 の計測で見直す」ための材料がない（ADR 0029）。初期値（合計 300MB / 100 ファイル）で始め、見直すのは ADR 0029 の件数の基準を満たしたときか、失敗の報告が来たときにした（ADR 0030 決定 4）。決定 5 のほかの項目と、ほかの決定は変えない。
- 実装の前提（`pdf-lib` は Worker の中でだけ読み込む、読めない PDF は結合のときに飛ばして名前と理由を出す、イベント、最初のリリースは ADR 0002 だけ）は ADR 0030 に書いた。

### 2026-10-07: 実装で決めた詳細

- **形（決定 1・2）**: 結合は `lib/pdf/merge.ts` の `mergePdfs`、Worker は `workers/merge.worker.ts`、ページの側の窓口は `lib/pdf/merge-in-browser.ts` の `mergeInBrowser`、メッセージの型は `lib/pdf/worker-messages.ts`。Worker は結合のたびに作り、終わったら閉じる（メモリも一緒に手放す）。`Worker` がないとき、またはモジュールの Worker を作れずに例外が出たときは、メインスレッドで `mergePdfs` を呼ぶ（そのときだけ `pdf-lib` を読み込む）。
- **入力からファイル名を外した（決定 1）**: 入力は `{ id, bytes }` にした。結合にファイル名は要らず、飛ばしたファイルは id で返して、ページの側で名前に戻す。Worker にファイル名を渡さないので、Worker の例外のメッセージにファイル名が入ることもない（ADR 0007）。出力は `{ bytes: Uint8Array | null, skipped: { id, reason }[] }`（読めるファイルが 1 つもなければ `bytes` は `null`。ADR 0030 決定 2）。
- **ライブラリ（決定 3）**: `pdf-lib@1.17.1` を続け、`package.json` でも `^` を外して版を固定した。`@cantoo/pdf-lib@2.11.1` と、同じ結合のコード（`load` / `copyPages` / `save`）を esbuild で圧縮して比べると、gzip で 179 KB と 252 KB（約 1.4 倍）だった。結合に要る API は `pdf-lib` で足りていて、大きくなる理由がない。
- **暗号化の見分け方（決定 4）**: `pdf-lib` の `EncryptedPDFError` は ES5 に変換されたクラスで、`instanceof` で見分けられなかった（ユニットテストで確かめた）。`PDFDocument.load(bytes, { ignoreEncryption: true })` で読み込み、`isEncrypted` で見分ける。
- **壊れたものの見分け方（決定 4）**: 先頭 1024 バイトに `%PDF-` がなければ読まない（PDF の仕様ではヘッダは先頭 1024 バイトのどこかにあればよい）。読み込みで例外が出たもの、ページが 1 つも取れないもの（`pdf-lib` は壊れたオブジェクトを読み飛ばすため）、ページのコピーで例外が出たものも、読めないものとして飛ばす。
- **追加のときの判定（決定 4）**: 追加のときの `file.type` の判定（PDF 以外が混ざったら全部を受け付けない）は変えていない。MIME が空の環境で弾かれる問題（B-8）は ADR 0009 の担当のまま。拡張子だけ `.pdf` のテキストは、ブラウザが拡張子から `application/pdf` を付けるので追加でき、結合のときに「読み込めないため」として飛ばす（E2E で確かめた）。
- **警告（決定 5）**: 合計 300MB または 100 ファイルを超えたら、操作のボタンの上に「ファイルの数か合計の大きさが大きいため、端末によっては時間がかかるか、失敗することがあります。」と出す（`constants/index.ts` の `MERGE_WARNING_*`）。超えたときに `size_warning_shown` を送る（`docs/analytics.md`）。
- **失敗の扱い**: Worker の中の例外は、メモリ不足（`RangeError` か、メッセージに out of memory / allocation failed を含むもの）を `out_of_memory`、それ以外を `worker_error` として返す。Worker の外の例外は `unknown`。`worker_error` と `unknown` だけを Sentry に送る（ADR 0030 決定 5）。
- **断りの文言（決定 7）**: 「ファイルはこの端末の中だけで処理され、外部へ送信されません。」に替え、鍵のアイコンを付けた。「社外秘の文書や個人情報を含むファイルは、アップロードしないでください。」は、送らなくなったので消した（ADR 0027 の追記）。CSP の `connect-src` は ADR 0017（別のリリース）で絞る。
- **計測**: 手元（Apple M4・Chromium）で、合計 100MB の結合は 270〜457 ms（3 回の走らせの中央値の幅）、結合中に 50ms 以上の Long Task は出なかった。数値は `docs/performance.md`。
